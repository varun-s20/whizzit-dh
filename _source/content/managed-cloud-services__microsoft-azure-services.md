### Why Azure bills surprise people

Azure is pay as you go, which sounds reassuring until the first bill arrives that nobody can explain. It is almost never one big mistake. It is a dozen small ones nobody owned.
- [CTA] Machines nobody revisited
Virtual machines get sized generously during a project and never revisited, so you pay for headroom you have never touched. Test environments spin up on a Tuesday and run all weekend because switching them off was somebody’s job in principle.
- [CTA] Orphans and missing tags
Disks and public IP addresses outlive the machines they belonged to and keep billing quietly on their own. Nothing is tagged, so when the bill goes up nobody can say which project or department caused it.
- [CTA] The wrong pricing model
Running everything at pay as you go rates when the workload is clearly permanent is the most common overspend we find. Reservations and savings plans exist precisely for predictable workloads, and applying them properly is often the single biggest reduction available without changing a thing technically.
- [CTA] It just needs looking at
None of this needs heroics. It needs somebody looking every month, which is what management means in practice rather than in a brochure.
Where the money usually leaks
- Virtual machines sized for a worst case that never arrives
- Dev and test environments running outside working hours
- Orphaned disks, snapshots and public IP addresses
- Pay as you go rates on permanently running workloads
- No tagging, so no accountability for spend
- Data egress nobody budgeted for

### The five things we actually do in Azure

This is the work we get asked for, so it is the work the page is about.

#### Migration

Moving servers and workloads off ageing on-premise hardware. Some things lift and shift unchanged, others are better re-platformed on the way across, and a few are genuinely better left where they are. We will tell you which is which rather than moving everything because it is billable.

#### Management and cost

Monitoring, patching, backups verified, capacity reviewed and spend examined every month. Right-sizing, reservations and switching off what nobody is using. This is the part that decides whether Azure saves you money or quietly costs more than the servers did.

#### Security

Identity first, because in Azure identity is the perimeter. Conditional access, multi-factor authentication, privileged access controlled rather than permanent, network segmentation, and alerting that reaches a human. We are Cyber Essentials Certified and apply the same standards here.

#### Backup and recovery

Backups configured, retained to a period you have actually chosen, held so ransomware cannot reach them, and tested by restoring rather than by looking at a green tick. Recovery objectives agreed per workload up front.

#### Virtual desktops

Azure Virtual Desktop where it genuinely fits, which is more often than people expect and less often than the marketing suggests. See below for the honest version.

#### Ongoing advice

As a Microsoft Cloud Solution Provider your licensing, support and escalation come direct from us rather than through a reseller chain, so when something needs Microsoft it goes to Microsoft.

### Virtual desktops, honestly

Azure Virtual Desktop earns its place in specific situations, and it is worth being clear about which. It is excellent when you need people working on company systems from equipment you do not control, so contractors, offshore teams, personal machines and anyone using their own laptop. It keeps the data in Azure rather than on the endpoint, which is a genuine security win. It suits a legacy application that refuses to behave on modern desktops. It is also the fastest way to onboard twenty people at once without waiting on hardware.

It is excellent when you need people working on company systems from equipment you do not control, so contractors, offshore teams, personal machines and anyone using their own laptop. It keeps the data in Azure rather than on the endpoint. It also suits a legacy application that refuses to behave on modern desktops, and it is the fastest way to onboard twenty people without waiting on hardware.
It is not automatically cheaper than buying laptops. Session hosts are virtual machines and they bill while they run, so the cost case depends entirely on sizing them properly and letting autoscale shut capacity down outside working hours. Get that wrong and you have bought an expensive way to run Windows. Profiles matter too, because user data has to live somewhere sensible or logins slow to a crawl, which is what FSLogix profile containers are for.
If you already have Microsoft 365 Business Premium or a Windows E3 or E5 plan, the desktop entitlement is typically already included, so you are paying Azure for the compute and storage rather than buying a whole new product. We will work out whether the numbers land in your favour before recommending it, and say so if they do not.

### Frequently asked questions

- [CTA] Do you manage Microsoft Azure?
- [CTA] Yes. We design, migrate, secure, back up and manage Azure environments, and we run Azure Virtual Desktop where it fits. As a Microsoft Cloud Solution Provider the licensing and support come direct from us, so escalation goes straight to Microsoft rather than through a reseller. -> /network-management/network-monitoring-services/
- [CTA] Can you actually control Azure costs?
- [CTA] Yes, and it is usually the quickest win available. Right-sizing machines that were sized for a worst case, shutting down test environments out of hours, removing orphaned disks and IP addresses, and applying reservations or savings plans to workloads that clearly run permanently. Then tagging everything so the next bill can be explained without a forensic exercise. -> /network-management/business-wifi-services/
- [CTA] Is Azure cheaper than our own servers?
- [CTA] Not automatically, and anyone who promises that without looking at your workloads is guessing. Azure wins clearly on variable demand, disaster recovery, avoiding a large hardware purchase, and anything you need to scale quickly. A steady predictable workload can cost more in Azure if it is left on pay as you go rates and never reviewed. The honest answer comes from modelling your actual usage. -> /network-management/managed-firewall-services/
- [CTA] Can you migrate our servers to Azure?
- [CTA] Yes, from a single workload up to your whole estate. Some servers move unchanged, some are better rebuilt on the way over, and occasionally the right answer is that something stays where it is for now. We work that out during discovery rather than moving everything and sorting it out later. -> /network-management/
- [CTA] Is Azure Virtual Desktop right for us?
- [CTA] It depends on the problem you are solving. It is strong for unmanaged or personal devices, contractors, keeping data off endpoints, awkward legacy applications and onboarding quickly. It is weaker as a straight cost saving against buying laptops, because session hosts bill while they run. If you already have Business Premium or Windows E3 or E5 the desktop entitlement is usually included, which changes the maths considerably. -> /cyber-security/penetration-testing-services/

- [CTA] Starting with identity, because that is the real perimeter. Multi-factor authentication enforced, conditional access, administrative rights granted temporarily rather than held permanently, and network segmentation so one compromised machine cannot reach everything.
